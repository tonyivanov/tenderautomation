# b2bcenter-scout

Парсер тендеров с площадки B2B-Center (b2b-center.ru) для GIS (Git in Sky).
Собирает актуальные тендеры по списку поисковых запросов, складывает в SQLite,
выгружает в txt для последующего разбора.

## Что это решает

На B2B-Center порядка 7-8 тысяч актуальных лотов в день, из них ~95% —
промышленность (металлургия, нефтегаз, ГОКи). Целевых под GIS-профиль
(IT-инфраструктура, ИБ, облака, поддержка) — десятки. Сплошной обход
неэффективен. Скрипт ходит через встроенный поиск площадки по
~94 заранее отобранным ключам и складывает все попадания.

## Архитектура

```
Прогон поиска (2b_search.bat)
  │
  ├─ fetch_list.py  ─→  ходит на /market/?f_keyword=... по 94 запросам
  │                     с защитой от шума и человекоподобными паузами
  │                     складывает в data/b2bcenter.db
  │
  └─ prefilter.py   ─→  помечает все search-тендеры как кандидаты (score=100)

Выгрузка (3_export.bat)
  │
  └─ export_for_review.py  ─→  data/score100_tenders.txt
                                data/all_tenders.txt
```

Финальная разметка происходит вручную — TXT отдаётся в чат с Claude,
и он отбирает реально интересные.

## Стандартный воркфлоу

После того как всё установлено (см. **DEPLOYMENT.md** для первой настройки):

1. Двойной клик `2b_search.bat` — соберёт свежие тендеры (~6 минут)
2. Двойной клик `3_export.bat` — выгрузит TXT
3. Загрузить `data/score100_tenders.txt` в чат с Claude (см. **CONTINUE_WITH_CLAUDE.md**)
4. Получить ранжированный список интересных тендеров

## Защита от антибота

- Случайные паузы 1.5-4 сек между страницами одного запроса
- 15% пауз — длинные «остановки на чтение» 8-15 сек
- Между разными запросами 2-4 сек
- На каждом запросе скрипт читает счётчик «Актуальных лотов: N»;
  если N > 1000, сервер вернул общий листинг вместо фильтра — запрос пропускается

## Особенности B2B-Center

- Параметр поиска: `?f_keyword=<слово>&searching=1&trade=all`
- Пагинация: `&from=N`, шаг 20
- Без авторизации видна вся выдача, но не полные карточки и не вложения
- Для работы с карточками нужна сессия GIS (через `4_login.bat`)
- Поиск по корням (морфология): «облак*» → «облако», «облачный»
- Кавычки делают точное совпадение, но в production-словаре они не используются —
  нашлось, что они режут больше, чем дают
