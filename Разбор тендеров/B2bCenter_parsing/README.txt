============================================
B2BCENTER-SCOUT — инструкция
============================================

Что это.
Скрипт ходит на ЭТП B2B-Center (b2b-center.ru), забирает все актуальные
тендеры из секций «Коммерческие закупки» и «223-ФЗ», складывает их
в локальную базу (data/b2bcenter.db) и помечает потенциальные кандидаты
для GIS — по правилам в keywords.yaml.

Архитектура двухуровневая:
  День 1 — обход списков /market/. Без авторизации, чистый HTML-парсинг.
  День 2 — заход внутрь карточек интересных тендеров: текст ТЗ, вложения,
           контакты заказчика. Здесь нужна авторизованная сессия GIS.

Для второго уровня — гибридная схема:
  Playwright (с настоящим Chromium) используется ОДИН РАЗ для логина —
  ты руками вводишь логин/пароль/2FA, скрипт сохраняет cookies.
  Дальше всё ходит через httpx с этими куками — быстро, незаметно,
  без лишнего браузера в памяти.


--------------------------------------------------
ШАГ 1. Что нужно установить
--------------------------------------------------

Python 3.10 или новее. Скачать: https://www.python.org/downloads/
При установке — обязательно поставь галку "Add Python to PATH".

Всё остальное (httpx, beautifulsoup4, lxml, PyYAML, playwright) поставит
1_setup.bat. Он же скачает Chromium для Playwright (~150 МБ, один раз).


--------------------------------------------------
ШАГ 2. Установка
--------------------------------------------------

Двойной клик по 1_setup.bat. Создаст папку venv\, поставит зависимости
и скачает Chromium. Делается один раз. Когда пишет «Готово» —
переходи к Шагу 3.


--------------------------------------------------
ШАГ 3. Логин в B2B-Center
--------------------------------------------------

Двойной клик по 4_login.bat.

Откроется окно Chromium с главной b2b-center.ru. Залогинься как обычно —
кнопкой "Войти", логин и пароль, при необходимости 2FA. Когда видишь
личный кабинет — переключись в чёрное окно терминала и нажми Enter.

Скрипт сохранит сессию в auth\auth_state.json. Этим файлом дальше
пользуется парсер карточек.

Срок жизни сессии — обычно сутки. Когда расширенный обход начнёт
жаловаться на 401/302 — просто запусти 4_login.bat ещё раз.


--------------------------------------------------
ШАГ 4. Сбор списков (День 1)
--------------------------------------------------

Двойной клик по 2_fetch.bat.

Что должно произойти:
  - откроется чёрное окно
  - скрипт сходит на /market/ (коммерческие) и /search-tender/zakupki/ (223-ФЗ)
  - покажет, сколько страниц всего и сколько новых тендеров скачал
  - применит префильтр и выведет статистику

Первый запуск — полный обход всех страниц. Около 8-10 минут.
Повторные запуски быстрые: скрипт идёт сверху, останавливается, когда
видит 5 знакомых тендеров подряд (значит, дальше всё уже в базе).

Для этого этапа авторизация НЕ требуется — /market/ отдаётся анонимам.

Если хочешь принудительно перекачать всё:
  venv\Scripts\python.exe fetch_list.py --section all --full


--------------------------------------------------
ШАГ 5. Выгрузка в txt и разбор
--------------------------------------------------

Двойной клик по 3_export.bat. Создаст:
  data\all_tenders.txt        — ВСЕ тендеры
  data\score100_tenders.txt   — только кандидаты после префильтра

Загрузи оба файла в чат. Я размечу, какие реально интересны, и оценю
качество префильтра — не выкидывает ли он нужное вместе с шумом.


--------------------------------------------------
ШАГ 6. Разведка карточек (для Дня 2)
--------------------------------------------------

После того как у нас есть список кандидатов и сохранённая сессия —
можно посмотреть, что отдаёт страница тендера авторизованному пользователю.

  5_recon.bat 4431469
  5_recon.bat https://www.b2b-center.ru/market/.../tender-4431469/
  5_recon.bat --top 3      # первые 3 кандидата из БД

Скрипт сохраняет в data\recon\:
  <id>.html           — полный HTML карточки
  <id>.png            — скриншот всей страницы
  <id>.report.json    — что нашлось: ОКПД, файлы, контакты

Покажи в чате 1-3 таких пакета — соберу парсер карточек,
который будет ходить по всем кандидатам автоматически.


--------------------------------------------------
КАК ПРАВИТЬ ПРЕФИЛЬТР
--------------------------------------------------

Открой keywords.yaml в Блокноте или VS Code. Внутри два списка:

  whitelist_keywords — слова, по которым тендер становится кандидатом
                       (score=100). Совпадение по подстроке, регистр игнорится.

  blacklist          — слова, по которым тендер сразу отсеивается (score=0).
                       blacklist приоритетнее whitelist.

Поправил файл — запусти ещё раз 2_fetch.bat. Префильтр перепроверит
ВСЕ тендеры в базе по новым правилам, скачивать заново ничего не надо.


--------------------------------------------------
ПРО АНТИБОТ И «ЧЕЛОВЕКОПОДОБНОСТЬ»
--------------------------------------------------

Площадка не любит ботов на /search/, но к авторизованной сессии относится
гораздо мягче — у тебя оплаченный аккаунт, ты её клиент.

В fetch_list.py и recon_card.py заложены случайные паузы 1.5-5 секунд
между запросами. Этого достаточно для большинства случаев.

Если начнут прилетать 403 на массовом обходе:
  1. Открой fetch_list.py
  2. Найди SLEEP_BETWEEN_PAGES = 1.5
  3. Поставь 3.0 или 5.0
  4. Запусти ещё раз

Большую human-imitation (движение мыши, паузы на «чтение») делать
смысла нет — она нужна для evading anti-bot fingerprinting на уровне
браузера, а у нас обычный httpx по куки авторизованной сессии.


--------------------------------------------------
ТИПИЧНЫЕ ОШИБКИ
--------------------------------------------------

"403 Forbidden"
  → Площадка временно режет частые запросы. Подожди 10-15 минут.
    Если повторяется — увеличь SLEEP_BETWEEN_PAGES в fetch_list.py.

"Не нашёл пагинатор"
  → Структура страницы могла поменяться. Скрипт продолжит работать,
    просто будет идти до первой пустой страницы. Сообщи в чате — поправлю.

"ModuleNotFoundError"
  → Не запустил 1_setup.bat или venv поломался. Удали папку venv\
    и запусти 1_setup.bat заново.

"recon_card.py: seems_login_wall: True"
  → Сессия истекла. Запусти 4_login.bat ещё раз.

"Скачал 0 тендеров с секции fz223"
  → У 223-ФЗ может быть другой URL пагинации. Это известная дыра —
    после первого запуска проверим и поправим.


--------------------------------------------------
СТРУКТУРА ПРОЕКТА
--------------------------------------------------

fetch_list.py          — обход /market/ и /search-tender/zakupki/
prefilter.py           — применение keywords.yaml к базе
export_for_review.py   — выгрузка в two txt-файла
login.py               — Playwright-логин на b2b-center.ru
recon_card.py          — забор и разбор одной карточки тендера
keywords.yaml          — правила фильтрации (можно править)
requirements.txt       — список python-пакетов
1_setup.bat            — установка
2_fetch.bat            — забор списков + префильтр
3_export.bat           — выгрузка в txt
4_login.bat            — логин на B2B-Center
5_recon.bat            — разведка карточки тендера
data/
  b2bcenter.db         — SQLite база
  all_tenders.txt      — выгрузка всех тендеров
  score100_tenders.txt — выгрузка кандидатов
  recon/               — HTML, скриншоты и отчёты по карточкам
auth/
  auth_state.json      — сессия Playwright (cookies + storage)
  cookies_debug.json   — копия кук в плоском виде
venv/                  — виртуальное окружение (не коммитим)
