# Персоны — TenderAutomation

## Персона 1: Аналитик тендеров

**Имя**: Даша (Аналитик)
**Роль в системе**: `analyst`

### Профиль
- **Должность**: Специалист по развитию бизнеса (BD), аналитик входящего потока тендеров
- **Технический уровень**: Высокий — уверенно работает с браузером, понимает procurement-домен, способна интерпретировать технические ТЗ в IT-тендерах
- **Частота использования**: Ежедневно, в начале рабочего дня

### Цели
- Быстро просматривать только релевантные тендеры, не тратя время на шум
- Работать в P1/P2 только с тендерами, у которых ещё не истёк известный дедлайн
- Находить просроченные тендеры в отдельном Архиве без потери истории решений
- Запускать AI-анализ для интересных кандидатов и получать структурированную оценку
- Передавать менеджеру готовую выборку с обоснованием

### Боли (сейчас)
- Вынуждена вручную разбирать TXT-файлы с сотнями тендеров
- Вставляет данные в claude.ai вручную — медленно и неудобно
- Нет единой истории по уже рассмотренным тендерам
- В P1/P2 встречаются тендеры с истёкшими или отсутствующими дедлайнами и нерабочими ссылками на площадку

### Типичный рабочий сценарий
1. Открывает веб-интерфейс и видит в P1/P2 только непросроченные тендеры
2. Просматривает карточки: название, заказчик, НМЦК, дедлайн, описание, каноническая ссылка на площадку
3. При необходимости открывает Архив, где недавно просроченные тендеры показаны первыми
4. Для перспективных запускает AI-анализ — видит эшелон и обоснование
5. Подготавливает шорт-лист для менеджера

### User Stories
- US-01 (автосбор), US-02 (квалификация), US-03 (JSONL-вывод), US-04 (просмотр и Архив), US-05 (AI-анализ), US-08 (надёжный дедлайн)

## Персона 2: Менеджер BD

**Имя**: Анастасия (Менеджер)
**Роль в системе**: `manager`

### Профиль
- **Должность**: Руководитель направления Business Development / партнёр
- **Технический уровень**: Средний — хорошо понимает бизнес и продуктовую специфику GIS, не погружается в технические детали системы
- **Частота использования**: Несколько раз в неделю, по уведомлению от аналитика

### Цели
- Быстро принимать обоснованные решения по тендерам
- Иметь прозрачный audit trail принятых решений
- Видеть историю — какие тендеры брали, какие отклоняли и почему

### Боли (сейчас)
- Нет единого лога решений — решения принимаются устно или в мессенджерах
- Нет возможности анализировать паттерны (по каким критериям отклоняли)

### Типичный рабочий сценарий
1. Получает уведомление в Telegram о новых квалифицированных тендерах
2. Открывает веб-интерфейс, просматривает шорт-лист от аналитика
3. Для каждого тендера нажимает «Взять в работу» / «Отклонить» / «Отложить», добавляет заметку
4. Периодически просматривает историю решений

### User Stories
- US-06 (принятие решений + лог), US-07 (история тендеров)

## Персона 3: Администратор системы

**Имя**: Максим (Администратор)
**Роль в системе**: `admin`

### Профиль
- **Должность**: Разработчик / DevOps — человек, который деплоит и поддерживает систему
- **Технический уровень**: Высокий — работает с CLI, конфиг-файлами, Python, сервером
- **Частота использования**: Редко — при деплое, добавлении новой площадки, обновлении фильтров

### Цели
- Простая extensible архитектура: добавление новой площадки без изменения ядра
- Конфигурирование системы через файлы (YAML-дескрипторы площадок, `.env`)
- Прозрачный мониторинг работы пайплайна
- Безопасное пакетное исправление существующих тендеров без прямого редактирования БД

### Боли (сейчас)
- Дублирование кода между двумя скраперами — правки нужно делать в двух местах
- Нет чёткого интерфейса для добавления новой площадки
- Нет управляемого способа восстановить отсутствующие дедлайны и исправить старые Bidzaar-ссылки

### Типичный сценарий восстановления данных
1. Открывает защищённую страницу `/admin` и запускает reconciliation с ограниченным размером пакета
2. Видит итоговые счётчики: проверено, обновлено, осталось без дедлайна, ошибки
3. При production-диагностике запускает ту же идемпотентную операцию через CLI
4. Повторяет обработку следующего пакета, не затрагивая уже исправленные записи

### User Stories
- US-01 (настройка сбора), US-02 (настройка фильтров), US-03 (форматы данных), US-09 (reconciliation)
