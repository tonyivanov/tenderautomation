# Code Quality Assessment

## Test Coverage
- **Overall**: None — автоматических тестов в проекте нет.
- **Unit Tests**: отсутствуют.
- **Integration Tests**: отсутствуют. Проверка — «тестируй на реальных данных» (ручная, по `bidzaar.db`).

## Code Quality Indicators
- **Linting**: не настроен (нет ruff/flake8/black-конфигов).
- **Code Style**: в целом консистентный, осмысленные docstring'и на русском, читаемые имена. Хорошая инлайн-документация бизнес-логики.
- **Documentation**: **сильная сторона** — подробные README/DEPLOYMENT/PROJECT_CONTEXT/WORKFLOW, история принятых решений, расшифровка схемы БД. Ориентировано на передачу не-разработчику и новой сессии Claude.

## Technical Debt
- **Дублирование паттерна** между `b2bcenter-scout` и `bidzaar-scout` (fetch/store/prefilter/export повторены) — нет общего ядра/модели тендера.
- **Нет lock-файла зависимостей** (`requirements.txt` с `>=`) → невоспроизводимые сборки; расхождение версий playwright.
- **«День 2» не реализован** — поля `details_fetched`, `llm_score`, `llm_verdict` в схеме есть, кода нет.
- **Платформенная привязка** к Windows `.bat`; Unix-запуск только вручную.
- **Жёстко зашитые селекторы/URL** парсинга B2B-Center — хрупки к смене вёрстки площадки.
- **Семантический разбор вне кода** (ручной чат) — не воспроизводимо, не версионируется, не масштабируется.

## Security Findings (приоритетно)
- 🔴 **Секреты в репозитории**: `playwright_state.json`, `token_cache.json`, `cookies.json`, `cookies_debug.json`, `auth_state.json` отслеживаются git и попали в первый коммит. README прямо предупреждает: *«playwright_state.json — НИКОМУ не показывай!»* — владелец файла может действовать в Bidzaar/B2B-Center от имени аккаунта ГИС.
  - **Действие**: добавить в `.gitignore`, удалить из индекса (`git rm --cached`), ротировать сессии, при публикации репозитория — переписать историю.
- 🟠 **Технический аккаунт раскрыт в документации**: `tender@gitinsky.com` (в PROJECT_CONTEXT.md, виден и в JWT). Не критично, но стоит учитывать.
- 🟠 **JWT/сессии в plaintext-файлах** на рабочей машине — приемлемо для локального инструмента, но не для шаринга/репозитория.

## Patterns and Anti-patterns
- **Good Patterns**: ETL-pipeline; config-as-data (YAML без правки кода); incremental sync + dedup; saved-session auth (обход 2FA); «золото не теряем» — мягкий префильтр + семантический финальный отбор; богатая документация и история решений.
- **Anti-patterns**: секреты в VCS; копипаста между конвейерами; отсутствие тестов и lock-файлов; хрупкий HTML-парсинг; ручной невоспроизводимый шаг анализа.

## Итоговая оценка
Прагматичный, рабочий **День 1** с отличной документацией и здравыми инженерными решениями для своего масштаба. Основные направления улучшения: (1) безопасность секретов, (2) автоматизация анализа (День 2), (3) общее ядро и тесты, (4) воспроизводимость сборки.
