# Уточнения: дедлайны и папка «Архив»

Контекст текущей реализации:

- у тендера уже есть независимый рабочий статус: `qualified`, `taken`, `deferred`, `rejected` и другие;
- текущий Bidzaar collector пропускает только вновь полученные записи, у которых дедлайн уже распознан и просрочен; ранее сохранённые просроченные записи остаются в БД, а записи без дедлайна сохраняются;
- вкладки P1 и P2 фильтруют по LLM-очереди, но не по состоянию дедлайна;
- B2B-Center читает дедлайн только из выдачи и не открывает карточку при отсутствии даты;
- Bidzaar сохраняет ссылку integrator API без нормализации, поэтому ссылки вида `/process/light/{id}` могут вести на 404 вместо канонического `/app/process/light/{id}`;
- отдельной папки или статуса «Архив» сейчас нет.

A) Как вычисляемая вкладка: тендер попадает в «Архив», когда его дедлайн меньше текущего времени; рабочий статус (`taken`, `deferred`, `rejected` и т. п.) сохраняется (рекомендуется)
