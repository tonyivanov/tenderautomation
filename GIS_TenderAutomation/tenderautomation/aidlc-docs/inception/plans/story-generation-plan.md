## Методология

Подход: **Feature-Based + Persona-Based (гибрид)**

Истории организуются по функциональным областям (эпикам) из требований, с явной привязкой к персоне. Этот подход выбран потому что:
- Требования уже структурированы по FR (FR-01 — FR-10)
- Разные персоны используют разные подсистемы
- Удобно для планирования итераций по эпикам

Эпики (предварительно):
1. **Сбор тендеров** (FR-01, FR-10) — автосбор, расписание, аутентификация
2. **Квалификация** (FR-02, FR-03) — платформенный слой, фильтры
3. **AI-анализ** (FR-04, FR-06) — JSONL, AGENTS.md, результаты агента
4. **Веб-интерфейс — просмотр тендеров** (FR-05, FR-09) — список, индикаторы, уведомления
5. **Веб-интерфейс — принятие решений** (FR-05, FR-07) — действия специалиста, лог
6. **История и аналитика** (FR-08) — лог тендеров, экспорт
7. **Администрирование** (FR-03, FR-10) — настройка фильтров, платформ, пользователей
